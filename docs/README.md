# OctoAcme Project Management Docs

Welcome to the OctoAcme Project Management documentation hub. This folder centralizes the core processes, roles, and practices used to plan, deliver, release, and improve work across OctoAcme projects.

## Overview

OctoAcme follows a structured, iterative project management approach designed to deliver customer value efficiently while keeping teams aligned, accountable, and learning continuously. Our process emphasizes:

- Customer-first delivery and usability
- Iterative, testable increments
- Clear ownership and role clarity
- Data-informed decision-making
- Psychological safety and continuous improvement

This documentation set is intended to help teams move from idea to execution with a clearer understanding of responsibilities, milestones, risks, and release practices.

## Project Management Process Summary

OctoAcme projects follow a five-stage lifecycle:

1. Initiation
   - Validate the business problem, stakeholder need, and success criteria.
   - Align stakeholders and confirm whether the work should proceed.

2. Planning
   - Create a backlog, define milestones, estimate effort, and establish a definition of done.
   - Identify dependencies, risks, and release timing.

3. Execution
   - Build features, track progress, resolve blockers, and maintain visibility through standups and reviews.
   - Keep work aligned to agreed quality, delivery, and communication practices.

4. Release
   - Prepare deployment artifacts, validate quality, and roll out changes with monitoring and rollback plans.
   - Communicate release readiness and post-deployment verification.

5. Retrospective and Continuous Improvement
   - Reflect on wins, lessons, and process gaps.
   - Capture action items and adjust practices for the next cycle.

## Role Snapshot

- Project Manager (PM): coordinates delivery, timelines, risks, and communication
- Product Manager (PdM): defines outcomes and prioritization
- Developers: implement and validate features against acceptance criteria
- QA/Testing: verifies quality and readiness for release
- Stakeholders: provide context, priority, and approval inputs

For detailed descriptions, see [OctoAcme Roles and Personas](octoacme-roles-and-personas.md).

## How to Use These Docs

- Start with the Overview or Initiation guide when a project is newly proposed
- Use planning and execution docs as work progresses
- Refer to release and retrospective guidance at key transition points
- Keep guidance current through regular updates and team feedback

These documents are designed to reduce reliance on tribal knowledge and make core project management practices easy to find, share, and evolve over time.
